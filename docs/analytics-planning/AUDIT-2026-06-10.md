## P0 BUGS (correctness, must-fix)

1. **Empty-state "No data" banner is dead — `Number()` chokes on formatted KPI strings** — `src/pages/analytics/AnalyticsWorkspace.jsx:401-405`. The KPI "has data" check does `Number(k.value) > 0`, but values are pre-formatted strings (`"₹1,25,000"`, `"45%"`, `"1,234"`) → all `NaN`, so the clause never fires. A page with real money/appointment KPIs but empty charts wrongly shows the orange "Nothing was recorded… view all-time" banner. Fix: `Number(String(k.value).replace(/[^0-9.-]/g,"")) > 0`, or carry a raw numeric field. **Effort: S.** Why: false "no data" state directly undermines trust in the whole dashboard. *(audit frontend-bug)*

2. **"Collected" KPI and its own trend/sparkline use two different formulas** — `pm-analytics-service/src/analytics/builders/financial.ts:171` vs `:89` (prev-window `:222`). Headline `collected = SUM(g − GREATEST(bal,0))` but `billingByPeriod` uses `SUM(g − bal)`, which feeds the collection-trend chart, the ledger table, AND the sparkline on the same card. With any advance (negative balance), the trend/ledger show collected > the headline, and collection can exceed billed. The card's number contradicts its own chart. Fix: pick one definition (the file's doc says `g − bal`) and use it in all three places + the prev-window aggregate. **Effort: S.** Why: a headline money number that disagrees with its adjacent chart is an obvious correctness failure. *(audit backend-bug)*

3. **Week grain silently downgraded to day in 6 operational reports** — `pm-analytics-service/src/analytics/builders/operational.ts:26` (uses at `:47,:294,:343,:386,:491,:527`). `fmt` has no `week` branch, so `grain='week'` maps to the daily format. A 90-day window (FE sets `grain='week'` for 11–92 days) returns ~90 daily buckets, then `LIMIT 12/18` truncates to the most recent ~12 **days** instead of 12 weeks → trend shows ~2 weeks of a 90-day selection. `appointments`/`consultation-channel`/`followups` also hardcode the axis label "Month" while bucketing by day. Fix: add `grain==='week' ? '%x-W%v'` to `fmt`; derive axis label from grain. **Effort: S.** Why: every multi-week trend chart is showing the wrong window. *(audit backend-bug)*

4. **OPD Overview KPIs/charts ignore the doctor filter entirely** — `pm-analytics-service/src/analytics/builders/operational.ts:85-269`. The `overview` branch builds its own queries that never reference `docFilter`/`W`; appointments, billing, prescriptions, trends and clinical "top X" stay business-wide. Selecting a doctor on the landing page (the first page users see) changes nothing, violating "doctor+clinic top filters only." Fix: apply doctor scope to appt/patient/billing aggregates + trend (appt tables `um_id`, `tbl_medicine_report.um_id`, billing `doctor_unique_id`). **Effort: M.** Why: the primary filter no-ops on the primary page. *(audit backend-bug; overlaps nav-ia doctor-scope finding & R006)*

5. **IPD "Beds occupied now" / BOR only count admissions inside the date window** — `pm-analytics-service/src/analytics/builders/ipd.ts:42-52,:120-129,:141`. `currentlyAdmitted` is computed under the `tapm_admitting_date BETWEEN :s AND :e` window, so a patient admitted before the window but still in-house is excluded. "Beds occupied now" / BOR are understated for any short window despite the label saying "now." Fix: compute current census from an **unwindowed** query (`SUM(tapm_discharge=0)` scoped only by business/hospital). **Effort: M.** Note: IPD is OPD-pivot-deferred (R045) — fix only if IPD code stays reachable; otherwise fold into the IPD-quarantine cleanup (P3 #10). *(audit backend-bug)*

6. **"By doctor" chart mis-grouped into "Money & collections" on every clinical page** — `src/pages/analytics/service.js:670`. `byDoctor` maps to a single "Money & collections" section, but diagnosis/drug/lab/consultations/procedures builders all return `byDoctor`. On clinical pages a money-section header appears with no money content. Fix: re-home `byDoctor` to "Doctor performance" (already in `SECTION_ORDER:656`); if billing needs it, rename the billing block (e.g. `revenueByDoctor`). **Effort: S.** Why: wrong section header on most clinical pages. *(audit nav-ia)*

7. **Procedures renders inpatient data in an OPD-only module without disclosure** — `src/pages/analytics/shell/analyticsNav.jsx:122` + `pm-analytics-service/src/analytics/builders/procedures.ts:34-57`. `clinical/procedure` is live and pulls `tbl_inpatient_doctor_procedure` (IPD source), presented silently as OPD procedures. Fix: either remove the `procedures` endpoint so it falls back to the honest PlaceholderPage, OR add a prominent provenance banner. **Effort: S.** Why: presents unvetted inpatient rows as OPD data the user never approved. *(R077/R118/R120; the deeper "re-source to RxPad surgical history" is P1 #5)*

8. **Customize reorder pushes the entire KPI band to the bottom** — `src/pages/analytics/AnalyticsWorkspace.jsx:112` + `components/CustomizeDrawer.jsx:30-31`. `writeOrder` never includes the KPI-band widget id, so the final `ws.sort` resolves it to `oidx=999` and sorts the whole band after every chart/table. Masked today only because `groupWidgets` re-buckets it into "Key metrics" (sorts first via `SECTION_ORDER`); on any single-section page (`showHeaders=false`) the KPIs render last after any reorder. Fix: exclude `kind==="kpis"` from the top-level order sort (or give the band sort weight −1). **Effort: S.** Why: latent reordering bug that surfaces on single-section pages. *(audit frontend-bug)*

9. **`consultations` newVsRepeat mislabels unique patients as "First visit"** — `pm-analytics-service/src/analytics/builders/consultations.ts:94-100`. Sets `First visit = DISTINCT patients`, so a returning patient is shown as a "first visit." Fix: relabel to "Unique patients" vs "Follow-up consults" (`consults − uniquePatients`), or compute true first-visit via `MIN(tcm_datetime)`. **Effort: S.** Why: a donut slice that says the literal opposite of the truth. *(audit backend-bug)*

10. **consultation-channel in-clinic trend drops NULL-flag rows; KPI and trend disagree** — `pm-analytics-service/src/analytics/builders/operational.ts:340-362`. Trend uses `inclinic = SUM(NOT VID)` (NULL → counted in neither series), while the KPI uses `total − video` (includes NULLs). Series can sum to less than total and the two in-clinic numbers disagree. Fix: `SUM(NOT COALESCE(VID,0))`. **Effort: S.** *(audit backend-bug)*

11. **Operational followups/pharmacy/pathology/consultation-channel/appointments ignore `hospitalId`** — `pm-analytics-service/src/analytics/builders/operational.ts:367-571` (shared `W` `:41`). Overview/footfall/patients honor optional single-hospital scope; these branches don't, so a multi-site business picking one clinic gets silently un-scoped data on those pages. Fix: thread `AND a.hm_id = :hid` when `q.hospitalId` is present. **Effort: M.** *(audit backend-bug)*

12. **Clinical trend charts (diagnosis/drug/lab/procedure) hardcode monthly bucketing** — `diagnosis.ts:53`, `drug.ts:54`, `lab.ts:71`, `procedures.ts:51`. They `DATE_FORMAT(...,'%Y-%m')` + label "Month" regardless of `q.grain`, while `consultations.ts` honors grain. On a 7-day window these collapse to one bar and look broken. Fix: add a grain param like consultations/footfall; label axis from grain. **Effort: S.** *(audit backend-bug; same family as #3)*
